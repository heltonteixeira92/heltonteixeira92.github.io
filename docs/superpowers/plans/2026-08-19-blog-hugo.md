# Migração para Blog em Hugo — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Substituir a SPA React do portfólio por um blog em Hugo, com feed único misturando posts de código e de viagem de moto, portfólio reduzido a uma página `/sobre`, e deploy automático via GitHub Actions.

**Architecture:** Site estático gerado por Hugo, com tema próprio escrito do zero (nenhum tema de terceiros). Zero JavaScript em runtime — o filtro de categorias são links para páginas de taxonomia que o Hugo gera. CSS puro num arquivo único, com custom properties para os dois temas de cor. Fontes self-hosted. Conteúdo em Markdown versionado no repositório; publicar é `git push`.

**Tech Stack:** Hugo extended v0.165.0 · Markdown · CSS puro · GitHub Actions · GitHub Pages

**Spec:** `docs/superpowers/specs/2026-08-19-blog-hugo-design.md`

## Global Constraints

- **Hugo extended, versão exatamente `0.165.0`**, fixada. A edição *extended* é obrigatória: codificação WebP só existe nela.
- **Idioma pt-BR** em todo o conteúdo, na interface e nos nomes de arquivo. `lang="pt-BR"` no HTML.
- **Zero JavaScript.** Nenhum `<script>` no site publicado. Se uma tarefa parecer exigir JS, ela está errada.
- **Nenhum recurso de terceiro em runtime.** Sem CDN, sem Google Fonts via link, sem analytics. Tudo servido do próprio domínio.
- **Um único arquivo CSS**: `assets/css/main.css`. Sem Tailwind, sem Sass, sem pré-processador.
- **Contraste mínimo AA (4.5:1)** para todo texto, nos dois modos de cor.
- **Nenhuma cor derivada do template antigo.** O azul `#576cbc` e o fundo `#212121` não reaparecem.
- `baseURL = "https://www.heltonteixeira.dev/"`.
- **Estrutura de templates nova (Hugo ≥ 0.146):** templates na raiz de `layouts/`, partials em `layouts/_partials/`, shortcodes em `layouts/_shortcodes/`. **Nunca** usar `layouts/_default/`, `layouts/partials/` ou `layouts/index.html` — foram removidos.
- **Commits em português**, no formato `tipo: descrição`.

## Nota sobre testes

Site estático não comporta testes unitários. O ciclo de teste de cada tarefa é:
**construir o site e afirmar sobre o HTML gerado em `public/`.** Um `grep` que
falha antes da implementação e passa depois é um teste de verdade — verifica o
comportamento observável, não a implementação.

Todas as verificações usam:

```bash
hugo --cleanDestinationDir -D
```

O `-D` inclui rascunhos; o `--cleanDestinationDir` garante que nenhum resultado
seja resíduo de um build anterior.

```toml

title = "Helton Teixeira"
languageCode = "pt-br"
defaultContentLanguage = "pt-br"
enableRobotsTXT = true

# Link interno quebrado derruba o build em vez de publicar um 404.
# Vale apenas para links escritos com os shortcodes ref/relref.
refLinksErrorLevel = "ERROR"

[taxonomies]
  categoria = "categorias"
  tag = "tags"

[params]
  descricao = "Blog pessoal sobre desenvolvimento backend e viagens de moto."

[markup]
  [markup.goldmark.renderer]
    unsafe = true
  [markup.highlight]
    noClasses = false      # usa classes CSS, para o highlight seguir o modo claro/escuro
    lineNos = false
    tabWidth = 2

[services]
  [services.rss]
    limit = 20
```

Duas escolhas que merecem explicação, porque não são óbvias:

`noClasses = false` faz o Hugo emitir `<span class="k">` em vez de estilo inline. É o que permite o bloco de código respeitar o modo escuro — com estilo inline, as cores ficariam presas ao tema claro.

`unsafe = true` no Goldmark permite HTML dentro do Markdown. É necessário para o shortcode de foto emitir `<figure>`, e é seguro aqui porque só você escreve o conteúdo.

- [ ] **Step 1: Escrever a verificação que falha**

Crie um post de teste e tente construir:

````bash
mkdir -p content/posts
cat > content/posts/fila-com-redis.md <<'EOF'
---
title: "Por que sua fila do Redis está mentindo"
date: 2026-07-02
categorias: ["codigo"]
tags: ["redis", "filas"]
resumo: "Todo mundo trata LPUSH como se fosse uma garantia. Não é."
draft: false
---

Uma fila no Redis parece simples até o primeiro worker morrer no meio do
processamento. `LPUSH` coloca o item na lista e `RPOP` tira. O problema é o
intervalo entre tirar e terminar de processar.

```python
item = redis.rpop("fila")   # o item saiu da fila
processa(item)              # se o worker morrer aqui, o item sumiu
```

O item não está mais na fila e não foi processado. Ninguém sabe que ele
existiu. É por isso que existe `RPOPLPUSH`: o item sai de uma lista e entra
numa lista de processamento na mesma operação atômica.
EOF

hugo --cleanDestinationDir -D
grep -q 'Por que sua fila do Redis' public/posts/fila-com-redis/index.html
````
Expected: FALHA. Sem layouts, o Hugo não gera `public/posts/fila-com-redis/index.html` e o `grep` retorna código 2 (arquivo inexistente).

- [ ] **Step 3: Criar `layouts/_partials/head.html`**

```html
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>{{ if .IsHome }}{{ site.Title }}{{ else }}{{ .Title }} · {{ site.Title }}{{ end }}</title>
  <meta name="description" content="{{ .Params.resumo | default site.Params.descricao }}">

  <link rel="preload" href="/fonts/serif.woff2" as="font" type="font/woff2" crossorigin>
  <link rel="preload" href="/fonts/mono.woff2" as="font" type="font/woff2" crossorigin>

  {{ with resources.Get "css/main.css" }}
    {{ $css := . | minify | fingerprint }}
    <link rel="stylesheet" href="{{ $css.RelPermalink }}" integrity="{{ $css.Data.Integrity }}">
  {{ end }}

  {{ with .OutputFormats.Get "rss" }}
    <link rel="alternate" type="application/rss+xml" href="{{ .Permalink }}" title="{{ site.Title }}">
  {{ end }}
</head>
```

O `fingerprint` põe um hash no nome do CSS, o que permite cache eterno no
navegador sem risco de servir versão velha depois de um deploy.

O `{{ with resources.Get ... }}` não falha se o CSS ainda não existir — o que
importa aqui, já que `main.css` só chega na Task 3.

```html

<article class="post">

    <time datetime="{{ .Date.Format "2006-01-02" }}">{{ .Date.Format "2006-01-02" }}</time>
    {{ with index .Params.categorias 0 }}

  <h1 class="titulo">{{ .Title }}</h1>

  <div class="prosa">
    {{ .Content }}
  </div>

  {{ with .Params.tags }}
    <footer class="tags">
      {{ range . }}

      {{ end }}
    </footer>
  {{ end }}
</article>
{{ end }}
```

O `index .Params.categorias 0` pega o primeiro (e único) valor da lista. É aqui
que a convenção "exatamente uma categoria por post" vira comportamento: se você
puser duas, a segunda é silenciosamente ignorada na exibição — embora o post
apareça nas duas páginas de taxonomia.

- [ ] **Step 2: Baixar as fontes**

Ambas vêm dos repositórios oficiais, não de CDN. Source Serif 4 é usada na
variante variável (um arquivo cobre todos os pesos), o que economiza requisições.

```bash
mkdir -p static/fonts /tmp/fontes && cd /tmp/fontes

curl -sSLO https://github.com/adobe-fonts/source-serif/releases/download/4.005R/source-serif-4.005_web.zip
curl -sSLO https://github.com/JetBrains/JetBrainsMono/releases/download/v2.304/JetBrainsMono-2.304.zip

unzip -oq source-serif-4.005_web.zip -d serif
unzip -oq JetBrainsMono-2.304.zip -d mono

DEST=/home/helton/SideProjects/heltonteixeira92.github.io/static/fonts
cp "$(find serif -name '*Variable*Roman*.woff2'  | head -1)" "$DEST/serif.woff2"
cp "$(find serif -name '*Variable*Italic*.woff2' | head -1)" "$DEST/serif-italica.woff2"
cp "$(find mono  -name 'JetBrainsMono-Regular.woff2' | head -1)" "$DEST/mono.woff2"
```

O `find` localiza os arquivos por padrão porque a estrutura interna dos zips
muda entre versões — depender do caminho exato quebraria numa atualização.

**Files:**

- [ ] **Step 2: Criar `layouts/_partials/filtro.html`**

Os três links são para páginas que o Hugo gera. **Não é filtro em JavaScript** — é o
que permite cada filtro ter URL própria, funcionar sem JS e ser indexável.

```html
<nav class="filtro" aria-label="Filtrar por categoria">
  <a href="{{ "/" | relURL }}"
     {{ if eq .atual "tudo" }}aria-current="page"{{ end }}>tudo</a>
  <a href="{{ "/categorias/codigo/" | relURL }}"
     {{ if eq .atual "codigo" }}aria-current="page"{{ end }}>~/codigo</a>
  <a href="{{ "/categorias/estrada/" | relURL }}"
     {{ if eq .atual "estrada" }}aria-current="page"{{ end }}>~/estrada</a>
</nav>
```

- [ ] **Step 3: Criar `layouts/term.html`**

Um só template atende os dois tipos de termo — uma categoria e uma tag —, e se
diferencia por `.Data.Plural`. Categoria mostra o filtro no topo (para o leitor
poder pular para o outro lado); tag não, porque tag não faz parte do filtro.

```html
{{ define "main" }}
  {{ if eq .Data.Plural "categorias" }}
    {{ partial "filtro.html" (dict "atual" .Data.Term) }}
  {{ else }}
    <h1 class="titulo">#{{ .Data.Term }}</h1>
  {{ end }}

  <ol class="lista">
    {{ range .Pages }}
      {{ partial "post-item.html" . }}
    {{ end }}
  </ol>
{{ end }}
```

- [ ] **Step 4: Criar `layouts/taxonomy.html`**

Índice de todos os termos de uma taxonomia — na prática, a página `/tags/`.

```html
{{ define "main" }}
  <h1 class="titulo">{{ .Title | lower }}</h1>
  <ul class="nuvem">
    {{ range .Data.Terms.Alphabetical }}
      <li>
        <a href="{{ .Page.RelPermalink }}">#{{ .Term }}</a>
        <span>{{ .Count }}</span>
      </li>
    {{ end }}
  </ul>
{{ end }}
```

- [ ] **Step 4: Criar `scripts/foto.sh`**

```bash
#!/usr/bin/env bash
#
# Redimensiona fotos antes de elas entrarem no repositorio.
#
#   scripts/foto.sh ~/fotos/viagem/*.jpg content/posts/nome-da-viagem/
#
# Git nunca esquece: uma foto de 8 MB commitada por engano fica no
# historico para sempre. A disciplina precisa estar na porta de entrada.

set -euo pipefail

if [ "$#" -lt 2 ]; then
  echo "uso: $0 <foto> [foto...] <pasta-do-post>" >&2
  exit 1
fi

destino="${!#}"
fotos=("${@:1:$#-1}")

if [ ! -d "$destino" ]; then
  echo "erro: '$destino' nao e um diretorio" >&2
  exit 1
fi

if command -v magick >/dev/null 2>&1; then
  im=(magick)
elif command -v convert >/dev/null 2>&1; then
  im=(convert)
else
  echo "erro: ImageMagick nao encontrado. Instale com: sudo apt install imagemagick" >&2
  exit 1
fi

for foto in "${fotos[@]}"; do
  nome="$(basename "${foto%.*}" | tr '[:upper:] _' '[:lower:]--')"
  saida="$destino/$nome.jpg"
  "${im[@]}" "$foto" \
    -auto-orient \
    -resize '2000x2000>' \
    -strip \
    -quality 82 \
    "$saida"
  printf '%-40s -> %s (%s)\n' "$(basename "$foto")" "$saida" "$(du -h "$saida" | cut -f1)"
done
```

Três detalhes que não são óbvios:

`-resize '2000x2000>'` — o `>` faz o ImageMagick **só reduzir**. Uma foto que já
seja menor passa intacta, em vez de ser ampliada e perder qualidade.

`-auto-orient` antes de `-strip` — o celular grava a rotação nos metadados EXIF.
Removendo o EXIF sem antes aplicar a rotação, fotos verticais saem deitadas.

`-strip` — remove todos os metadados, **inclusive as coordenadas de GPS**. Foto de
viagem de moto costuma carregar a localização exata de onde você parou, e publicar
isso não é o que você quer. A remoção é deliberada, não um efeito colateral.

- [ ] **Step 2: Criar `.github/workflows/deploy.yml`**

```yaml
name: Publicar no GitHub Pages

on:
  push:
    branches: [master]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

# Uma publicacao por vez. cancel-in-progress: false para nao abortar um
# deploy ja em andamento — publicacao pela metade e pior que publicacao lenta.
concurrency:
  group: pages
  cancel-in-progress: false

defaults:
  run:
    shell: bash

jobs:
  construir:
    runs-on: ubuntu-latest
    env:
      # Versao fixada de proposito. Com "latest", um release novo do Hugo
      # poderia quebrar o site sem ninguem ter mexido em nada.
      HUGO_VERSION: 0.165.0
      # Sem isso as datas dos posts sao interpretadas em UTC e um post
      # publicado a noite aparece com a data do dia seguinte.
      TZ: America/Sao_Paulo
    steps:
      - name: Instalar o Hugo extended
        run: |
          wget -O "${{ runner.temp }}/hugo.deb" \
            "https://github.com/gohugoio/hugo/releases/download/v${HUGO_VERSION}/hugo_extended_${HUGO_VERSION}_linux-amd64.deb"
          sudo dpkg -i "${{ runner.temp }}/hugo.deb"

      - name: Checkout
        uses: actions/checkout@v7

      - name: Configurar o Pages
        id: pages
        uses: actions/configure-pages@v6

      - name: Restaurar o cache do Hugo
        uses: actions/cache/restore@v6
        with:
          path: ${{ runner.temp }}/hugo_cache
          key: hugo-${{ github.run_id }}
          restore-keys: hugo-

      - name: Construir o site
        run: |
          hugo build \
            --gc \
            --minify \
            --baseURL "${{ steps.pages.outputs.base_url }}/" \
            --cacheDir "${{ runner.temp }}/hugo_cache"

      - name: Salvar o cache do Hugo
        uses: actions/cache/save@v6
        with:
          path: ${{ runner.temp }}/hugo_cache
          key: hugo-${{ github.run_id }}

      - name: Enviar o artefato
        uses: actions/upload-pages-artifact@v5
        with:
          path: ./public

  publicar:
    runs-on: ubuntu-latest
    needs: construir
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Publicar no Pages
        id: deployment
        uses: actions/deploy-pages@v5
```

O cache de imagens funciona pelo par `--cacheDir` + `actions/cache`: sem ele, o
Hugo reprocessa todas as fotos de todas as viagens a cada push, inclusive quando
você só corrigiu uma vírgula.

A chave usa `github.run_id` (sempre novo) com `restore-keys: hugo-` (casa com o
cache anterior). Esse par salva um cache atualizado a cada execução e ainda
aproveita o da execução passada.

`categorias` alimenta o filtro da home e aceita **um** valor. O Hugo não valida
isso — se você escrever `codgio`, o post some do filtro em silêncio. Use sempre o
`hugo new`, que já preenche certo.

## Post com fotos

Post com foto vira uma pasta, com as imagens junto do texto:

```bash
hugo new content posts/nome-da-viagem/index.md
scripts/foto.sh ~/fotos/viagem/*.jpg content/posts/nome-da-viagem/
```

O script reduz para no máximo 2000px, qualidade 82, e **remove os metadados EXIF
— incluindo as coordenadas de GPS**. Rode sempre antes de commitar: git nunca
esquece, e uma foto de 8 MB fica no histórico para sempre.

No texto:

```markdown
{{< foto src="curva-01.jpg" legenda="A subida, já dentro da neblina." >}}
```

A legenda também vira o texto alternativo. `src` errado derruba o build em vez de
publicar imagem quebrada.

## Publicar

```bash
git add . && git commit -m "post: título" && git push
```

O GitHub Actions constrói e publica em cerca de 40 segundos. Não existe passo
manual de deploy.

Dá para escrever pelo `github.com` direto do celular — útil na estrada.
